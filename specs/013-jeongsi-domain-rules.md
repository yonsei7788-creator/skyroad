## 1. 지원 가능성 분류 임계값

### 1.1 "환산 총점 대비 비율" 은 대학 간 공통 임계값의 척도로 부적절하다

`PlanEvaluation.gapRatio` 는 `(학생 환산점수 − 컷) / totalScore × 100` 입니다. 이 값에 **모든 대학 공통 임계값**을 적용하면 안 됩니다.

이유: **환산점수의 백분위 민감도가 대학마다 2배 이상 차이납니다.** 반영비율 합이 같아도, 영어가 비율에 포함되면 국·수·탐이 차지하는 비중이 줄어들고, 백분위 지표는 표준점수 지표보다 상위권 변별이 작습니다.

샘플 데이터(`admission-plans-2027.json`)의 경영계열 모집단위에서 백분위 96 → 97 로 1점 올렸을 때 환산점수 변화를 측정한 결과:

| ---------- | --------- | -------------- | ------------------- | ------------------------------ |
| 서울대     | 600       | 표·표/변환표준 | **1.583**           | 1.90 백분위점                  |
| 고려대     | 1000      | 표·표/변환표준 | 1.565               | 1.92                           |
| 한양대     | 1000      | 표·표/변환표준 | 1.451               | 2.07                           |
| 서강대     | 1000      | 표·표/변환표준 | 1.381               | 2.17                           |
| 경희대     | 800       | 표·표/변환표준 | 1.362               | 2.20                           |
| 연세대     | 1000      | 표·표/변환표준 | 1.283               | 2.34                           |

정시에서 국·수·탐 평균 백분위 4점 차이는 대학 한두 단계에 해당합니다. 즉 잠정안을 그대로 쓰면 **백분위형 대학에서 "적정" 이 과도하게 넓어져, 명백한 상향과 명백한 안정이 같은 "적정" 으로 묶입니다.** 반대로 표준점수형 대학에서는 적정이 너무 좁아 추천 3개를 채우지 못합니다.

### 1.2 확정: 백분위 환산 격차(`percentileGap`)로 분류한다

**① 민감도 산출** (수치미분, 엔진이 계산)

> **2026-11-05 변경 (사용자 결정): 백분위→표준점수 기울기표는 폐기한다.** 원문 값이 아니다.
> 민감도는 백분위만 1점 올렸을 때의 환산점수 변화로 구한다. 백분위·변환표준점수(원문 표를 백분위로
> 찾음)로 환산하는 대학은 이것으로 정확하다. 표준점수를 반영하는 대학은 원문만으로 민감도를 구할 수
> 없어 `null` 이고, 그런 대학의 환산점수 입결은 백분위 격차로 바꾸지 않는다(비교할 수 없는 컷).
> 현재 데이터에서 환산점수 입결로 분류하는 216개는 모두 백분위 기반이라 분류는 바뀌지 않았다.
> 표준점수 반영 대학은 PART 5 의 "등급 손실이 백분위 약 X점 상당" 판정을 쓰지 않는다.
> 아래 기울기표와 설명은 기록으로 남긴다.
>
> **같은 날 함께 폐기:** 가중치 공시 대학(국100·수120·탐80 등) 중 표준점수를 반영하는 곳(고려대·
> 연세대·경북대 183개)은 영역 비중(%)을 원문에 없는 표준점수 최고점(140·72)으로 역산한다. 환산점수는
> 지표 × 계수라 정확하지만 비중은 추정값이므로 `plan.areaSharesEstimated` 로 표시하고, 비중 비교·
> 유리도 기본 점수·가중 백분위·PART 5 비중 판정에 쓰지 않는다(유리도 기본 점수는 50).

```
sensitivity = ( eval(학생 국·수·탐 백분위 각 +1) − eval(학생 원점수) ) / totalScore × 100
```

영어·한국사는 등급이 그대로이므로 상쇄되어 영향이 없습니다.

⚠️ **백분위를 +1 할 때 표준점수도 함께 올려야 합니다.** 표준점수 지표 영역은 환산에 `standardScore` 를 쓰므로, 백분위만 올리면 지표값이 움직이지 않아 민감도가 0 이 됩니다. 아래 **백분위→표준점수 기울기**를 쓰세요.

| 백분위 구간 | 국어·수학 | 탐구 | 비고                          |
| ----------- | --------- | ---- | ----------------------------- |
| 99 ~ 100    | 5.0       | 2.0  | 최상단은 기울기가 급격히 커짐 |
| 98 ~ 99     | 3.0       | 2.0  |                               |
| 95 ~ 98     | 2.0       | 1.0  | 정시 상위권 주 구간           |
| 94 ~ 95     | 1.0       | 1.0  |                               |
| 92 ~ 94     | 1.5       | 1.0  |                               |
| 90 ~ 92     | 1.0       | 0.5  |                               |
| 85 ~ 90     | 1.0       | 0.67 |                               |
| 80 ~ 85     | 0.8       | 0.4  |                               |
| 60 ~ 80     | 0.6       | 0.4  |                               |
| ~ 60        | 0.6       | 0.3  |                               |

🔴 **고정 상수(예: 국·수 2.0 / 탐구 1.0)를 전 구간에 쓰면 안 됩니다.** 그 값은 백분위 95~98 구간에서만 맞습니다. 백분위 99 학생은 실제 기울기가 5.0 인데 2.0 을 쓰면 민감도가 2.5배 과소평가되어 `percentileGap` 이 2.5배 과대평가됩니다(의대 지원권이 전부 안정/지원불가로 쏠림). 반대로 백분위 80 학생은 실제 0.8 인데 2.0 을 쓰면 민감도가 2.5배 과대평가되어 격차가 압축되고 전부 적정으로 쏠립니다.

이 표는 `libs/jeongsi/data/*.json` 의 입결 컷을 생성할 때 쓴 것과 **동일한 대응표**이므로, 이 값을 쓰면 엔진과 샘플 데이터가 정확히 일치합니다.

> 📌 실데이터 전환 시: 이 표는 2026 수능 백분위↔표준점수 관계의 **추정치**입니다. 수능 성적 발표 후 **실제 대응표로 교체**하세요. 교체하면 민감도 정확도가 그대로 올라갑니다.

**② 백분위 환산 격차**

```
입결 지표가 convertedScore 인 경우:  percentileGap = gapRatio / sensitivity
입결 지표가 percentile   인 경우:  percentileGap = gapRatio          ← 나누지 않는다
```

> ⚠️ 엔진 구현 주의: 입결이 백분위로 공개된 경우 `gapRatio` 자체가 이미 백분위점 단위입니다(§6.2). 여기서 다시 `sensitivity` 로 나누면 격차가 1.3배 과대평가됩니다. 샘플 데이터는 두 지표가 섞여 있으므로 반드시 분기해야 합니다.

**③ 컷 변동성 σ** (백분위점)

```
σ_obs  = 최근 3개년 70%컷(백분위 환산)의 표본표준편차   // 2개년 이상일 때만
σ_min  = quota ≤ 15 → 1.5 | 16 ≤ quota ≤ 40 → 1.0 | quota ≥ 41 → 0.7
σ      = min(max(σ_obs, σ_min), σ_max)   // 3개년 데이터가 1개년뿐이거나 없으면 σ = σ_min. σ_max = 3.0
```

모집인원이 적을수록 컷이 요동칩니다. 10명 뽑는 학과의 70%컷은 상위 7등의 성적이라 한두 명의 지원 여부로 백분위 1~2점이 움직입니다. 모집인원 100명 학과는 거의 안 움직입니다. **모집인원을 변동성 하한에 반영하는 것이 이 모델의 핵심**입니다.

σ_min 은 "컷 자체의 변동성" 만이 아니라 **예측 전체의 불확실성**을 담습니다: 기준컷이 3개년 가중평균 + 보정으로 만든 추정치라는 점, 지원자 풀이 해마다 달라지는 점이 모두 여기 들어갑니다. 그래서 컷 변동이 작은 대규모 모집단위에도 0.7 의 하한을 둡니다.

**σ_max = 3.0 인 이유**: 소규모 모집단위는 한 해 튄 값으로 σ_obs 가 11 을 넘습니다(성신여대 경제학과 66.66→83). 상한이 없으면 +17 백분위점 여유가 적정이고, 다른 대학의 +8 은 안정이라 학생이 보는 순서가 뒤집힙니다. 상한 3.0 이면 +6 이상은 어느 대학이든 안정입니다.

**상향의 낮음/매우낮음 절대 하한 −1.5 백분위점**: σ_min 0.7 인 대규모 모집단위는 −1.6σ 가 −1.12 라, 같은 1.2점 부족이 모집인원에 따라 낮음·매우낮음으로 갈렸습니다(서울대 −1.2 매우낮음 / 고려대 −1.3 낮음). `gap ≥ min(−1.6σ, −1.5)` 이면 낮음입니다.

**σ_min 초기값(0.5/0.8/1.2)에서 상향 조정한 이유**: 샘플 데이터로 검증한 결과 σ=0.5 에서는 적정 구간 폭이 1.2 백분위점뿐이어서, 인접 대학 간 컷 간격(평균 약 0.9 백분위점)보다 좁아 **밴드가 대학 사이에 끼어 아무것도 못 잡는** 현상이 생겼습니다. 평균 백분위 87.3 학생의 경영계열 분류가 `지원불가 13 / 상향 2 / 안정 4 / 적정 0` 으로 **적정이 비었습니다.** 세 성향 조합 모두 적정 슬롯을 포함하므로 PART 3·4 가 통째로 깨집니다. 0.7/1.0/1.5 로 올리면 같은 학생이 `적정 2 / 상향 2 / 안정 2` 가 됩니다.

**④ 분류 임계값**

| tier         | 조건                            | σ=0.7 기준 환산 | 실무적 의미                                          |
| ------------ | ------------------------------- | --------------- | ---------------------------------------------------- |
| **안정**     | `percentileGap ≥ +2.0σ`         | ≥ +1.40         | 3개년 최고 컷보다도 위. 변동을 흡수함                |
| **적정**     | `−0.4σ ≤ percentileGap < +2.0σ` | −0.28 ~ +1.40   | 70%컷 근처 ~ 여유권. 합격이 기본선이지만 보장은 없음 |
| **상향**     | `−2.2σ ≤ percentileGap < −0.4σ` | −1.54 ~ −0.28   | 컷 아래. 변동이 유리하게 작용해야 합격               |
| **지원불가** | `percentileGap < −2.2σ`         | < −1.54         | 3개년 어느 해에도 합격선에 닿지 못함                 |

**임계값 근거**

- **안정 `+2.0σ`**: 정시는 지원 후 성적이 변하지 않으므로, 불확실성은 "컷이 어디까지 오를 수 있는가" 뿐입니다. 정규 근사에서 2σ 는 상방 꼬리 약 2.3%. 즉 "컷이 올라서 떨어질 확률 2~3%" 수준을 안정의 정의로 삼았습니다. 정시 3장 중 1장이 이 조건을 만족하면 "최소 하나는 붙는다" 가 성립합니다.
- **적정 하한 `−0.4σ`**: 70%컷은 **충원합격자까지 포함한 최종등록자** 기준이므로 이미 추합을 반영한 실질 합격선입니다. 따라서 컷에 정확히 걸치면(gap=0) 합격 확률이 50%를 넘습니다. 컷을 소폭 밑도는 구간까지 적정에 포함시키는 것이 실무 감각에 맞습니다. −0.4σ 는 σ=0.7 에서 백분위 0.28점 — 체감상 "거의 동점" 범위입니다.
- **상향 하한 `−2.2σ`**: 하방 2.2σ 는 약 1.4% 꼬리. 컷이 그만큼 내려오는 일은 모집인원이 급증하거나 해당 학과가 급격히 기피되는 특수 상황에서만 일어납니다. 그보다 아래는 "운을 기대하는 지원" 이 아니라 **버리는 카드**이므로 지원불가로 분류해 추천에서 제외합니다.
- **잠정안 대비**: 잠정안의 "−4% 미만 지원불가" 는 서울대 기준 −2.5 백분위점, 인하대 기준 −5.3 백분위점입니다. 후자는 사실상 모든 상향 지원을 허용하게 되어 리포트 신뢰도를 해칩니다.

**⑤ 고정값 대체안 (σ 계산을 생략할 경우)**

3개년 컷 데이터 품질이 불안정한 초기에는 `σ = 0.7` 고정으로 단순화할 수 있습니다.

| tier     | percentileGap 조건 |
| -------- | ------------------ |
| 안정     | ≥ +1.4             |
| 적정     | −0.3 ~ +1.4        |
| 상향     | −1.5 ~ −0.3        |
| 지원불가 | < −1.5             |

단, **모집인원 15명 이하 모집단위에만 σ=1.5 를 적용**하는 최소 분기는 넣어 주세요. 소규모 학과의 오분류가 사용자 체감 오류의 대부분을 차지합니다.

### 1.3 `gapRatio` 필드의 용도

타입을 바꾸지 않습니다. `gapRatio` 는 **그대로 저장·표시**하되 분류 근거로는 쓰지 않습니다.

- `PlanEvaluation.gapRatio`: 기존 정의대로 저장 (환산 총점 대비 % 또는 백분위점 차)
- `tier` / `chance`: `percentileGap` 으로 산출
- `RecommendationItem.gapRatio`: 화면 표시용. 단위 라벨을 반드시 붙여야 함 (§6.2)

> 📌 **보고 사항**: `PlanEvaluation` 에 `percentileGap: number | null` 과 `sensitivity: number` 필드를 추가하면 디버깅과 AI 프롬프트 품질이 크게 올라갑니다. 타입 수정 권한이 없어 제안만 남깁니다.

## 2. PassChance ↔ AdmissionTier 대응

### 2.1 1:1 대응은 쓰지 않는다

`안정→높음 / 적정→보통 / 상향→낮음 / 지원불가→매우낮음` 으로 매핑하면 `chance` 가 `tier` 의 동어반복이 되어, 리포트에서 두 필드를 나란히 보여줄 가치가 없어집니다. 또한 **적정 구간이 −0.28 ~ +1.40 백분위점(σ=0.7)으로 넓어서**, 그 안에서 합격 가능성 차이가 실제로 큽니다.

`상향상단` 을 −1.2σ 에서 **−1.6σ** 로 조정했습니다. −1.2σ 에서는 평균 백분위 96.3 학생이 연·고대 경영(컷 97.2~97.3, 약 1 백분위점 부족)에 `매우낮음`(8~20%)을 받았습니다. 1 백분위점 부족은 정시 실무에서 전형적인 **소신지원**이고 20~40%(`낮음`)가 맞습니다. −1.6σ 로 두면 상향 밴드의 상위 약 73% 가 `낮음`, 하단 27% 만 `매우낮음` 이 됩니다.

### 2.2 확정 매핑

tier 내부를 `percentileGap` 으로 한 번 더 쪼갭니다.

| tier         | 추가 조건               | `chance`   | 추정 합격률 |
| ------------ | ----------------------- | ---------- | ----------- |
| **안정**     | (전체)                  | `높음`     | 85% 이상    |
| **적정**     | `percentileGap ≥ +0.8σ` | `높음`     | 65 ~ 85%    |
| **적정**     | `percentileGap < +0.8σ` | `보통`     | 40 ~ 65%    |
| **상향**     | `percentileGap ≥ −1.6σ` | `낮음`     | 20 ~ 40%    |
| **상향**     | `percentileGap < −1.6σ` | `매우낮음` | 8 ~ 20%     |
| **지원불가** | (전체)                  | `매우낮음` | 8% 미만     |

이 매핑으로 4개 라벨이 모두 의미 있게 쓰입니다. `report-types.ts` 의 `RecommendationItem` / `CombinationSlot` / `UniversityDetailItem` 은 tier 에서 `지원불가` 를 제외하므로, **리포트에 노출되는 `매우낮음` 은 "상향 하단" 을 뜻합니다.**

### 2.3 "안정" 과 "적정 상단" 이 모두 `높음` 인 이유

의도된 설계입니다. 두 구간의 합격 확률 차이는 85% 대 75% 수준으로 라벨을 나눌 만큼 크지 않습니다. 둘의 진짜 차이는 확률이 아니라 **지원 전략상의 역할**(안정 = 3장 중 반드시 하나는 붙는 카드)이고, 그 역할은 `tier` 가 이미 표현합니다.

### 2.4 추정 기반일 때의 하향

`referenceCut` 이 추정값이면(신설 모집단위, cut70 결측 등 — §6) `chance` 를 **한 단계 내립니다**: `높음→보통 → 낮음 → 매우낮음`. `tier` 는 내리지 않습니다. 추정의 불확실성은 "확률" 쪽에 반영하는 것이 사용자에게 정직하고, tier 를 내리면 추천 목록 구성이 깨집니다.

## 3. 보정 변수

### 3.1 3개년 입결 추세 — 사용한다

**① 기준컷은 단년이 아니라 3개년 가중평균**

```
weights = { 2026: 0.5, 2025: 0.3, 2024: 0.2 }
baseCut = Σ(cut_y × w_y) / Σ(w_y)        // 결측 연도는 제외하고 가중치 재정규화
```

근거: 최근 연도가 지원자 풀·수능 체제 면에서 가장 유사하므로 가장 큰 가중치를 줍니다. 그러나 단년 컷은 "작년에 그 학과가 유행했는지" 같은 일회성 쏠림에 과민합니다. 실제로 정시 입결은 2~3년 주기로 선호가 진동하는 학과가 많아, 직전 연도만 쓰면 **진동의 꼭대기나 바닥을 기준선으로 잡는 사고**가 납니다.

**② 추세는 절반만, 상한을 두고 반영**

```
trend   = (cut_2026 − cut_2024) / 2                     // 연평균 변화, 백분위점
adjust  = clamp(trend, −1.0, +1.0) × 0.5
refCut  = baseCut + adjust
```

근거: 3개년이 단조 증가·감소면 추세가 2027에도 이어질 가능성이 있지만, **평균회귀 가능성도 그만큼 있습니다.** 어느 쪽인지 사전에 알 수 없으므로 절반만 반영하고 ±0.5 백분위점으로 상한을 둡니다. 추세 반영은 저보정이 과보정보다 안전합니다 — 과보정은 상향을 적정으로 잘못 승격시켜 사용자가 실제로 지원했다가 떨어지는 결과를 만듭니다.

3개년이 2개년 이하면 `trend = 0` (보정 없음).

### 3.2 모집인원 변화 — 사용한다 (데드존 + 상한)

```
avgQuota    = 최근 3개년 quota 의 평균
quotaChange = (plan.quota − avgQuota) / avgQuota
if |quotaChange| < 0.10 → 보정 0                        // 데드존
refCut     −= clamp(quotaChange, −0.4, +0.4) × 1.2      // 백분위점
```

근거: 모집인원이 늘면 합격선이 내려가는 관계는 정시에서 실증적으로 뚜렷합니다(같은 지원자 풀에서 더 많이 뽑으므로). 다만 **효과 크기는 작습니다.** 모집인원이 20% 늘어도 컷은 백분위 0.24점 정도만 내려갑니다. 모집인원이 2배가 되는 극단적 경우에도 상한 0.48점으로 묶습니다.

데드존을 둔 이유: 모집인원은 수시 이월 때문에 매년 10% 내외로 흔들립니다. 그 수준의 변동을 신호로 읽으면 노이즈를 증폭시킵니다.

### 3.3 경쟁률·충원인원 — 보정에 쓰지 않는다

**경쟁률은 쓰지 마세요.** 정시 경쟁률은 합격선과 거의 무상관입니다.

- 정시는 가·나·다군 3장을 쓰므로 한 학생이 세 번 카운트되고, 상위권 학생의 "버리는 카드" 지원이 경쟁률을 부풀립니다.
- 경쟁률이 높은 해에 오히려 컷이 내려가는 사례가 흔합니다(허수 지원 증가).
- 경쟁률을 보정 변수로 넣으면 명백한 오분류를 만듭니다.

**충원인원도 보정에 쓰지 마세요.** 70%컷은 **최종등록자** 기준이므로 추가합격자가 이미 포함되어 있습니다. 충원인원을 다시 반영하면 **이중 계산**입니다.

두 필드는 `UniversityDetailItem.competitionRate` 처럼 **정보 제공용으로만** 표시하고, AI 해설에서 "경쟁률이 높으니 어렵다" 류의 서술을 하지 않도록 프롬프트에 제약을 넣어야 합니다.

### 3.4 보정 적용 순서

```
1. cut70 선택 (없으면 cut50/average 대체 + 보정, §6.3)
2. 3개년 가중평균 → baseCut
3. 추세 보정        (±0.5 상한)
4. 모집인원 보정    (±0.48 상한, 10% 데드존)
   → refCut 확정
5. percentileGap = (학생 성적 − refCut) 을 지표에 맞게 산출 (§1.2 ②)
6. σ 산출 → tier / chance 분류
```

보정 총합은 최대 ±0.98 백분위점입니다. σ=0.7 기준 적정 구간 폭(1.68점)의 약 6할로, 분류를 한 단계 뒤집을 수는 있지만 두 단계 이상 움직이지는 못합니다. 의도한 설계입니다.

## 4. PART 4 — 성향별 군 배분 매트릭스

### 4.1 잠정안의 구조적 문제: 군은 대칭이 아니다

잠정안은 `안정=적정/안정/안정` 처럼 가·나·다군에 tier 를 **순서대로 지정**하는 형태입니다. 두 가지 문제가 있습니다.

**① 다군 선택지가 실제로 희소합니다.** 샘플 데이터 156개 모집단위 중 다군은 18개(11.5%)이며, 이는 실제 정시 구조를 반영한 것입니다. 상위권으로 갈수록 더 심해집니다 — 서울대·연세대·고려대·서강대·성균관대는 다군 모집이 없습니다. **백분위 98 학생에게 다군 선택지는 사실상 존재하지 않습니다.**

**② 어느 군에 상향을 둘지는 학생의 희망 학과가 어느 군에 있느냐로 결정됩니다.** 희망 학과가 나군에 있으면 나군이 상향 슬롯이어야 합니다. 군 순서를 고정하면 "희망과 무관한 학과로 상향 지원" 하는 추천이 나옵니다.

### 4.2 확정 매트릭스 — tier 집합(multiset)으로 해석

매트릭스는 **"세 장에 어떤 tier 를 몇 개 섞는가"** 만 규정하고, 군 배정은 별도 규칙(§4.3)으로 결정합니다.

| 지원 성향 | tier 구성              | 추가 제약                                                            |
| --------- | ---------------------- | -------------------------------------------------------------------- |
| **안정**  | {적정, 적정, **안정**} | 안정 슬롯은 `chance=높음` 이고 `percentileGap ≥ +2.5σ` 인 최상위 1개 |
| **균형**  | {상향, 적정, 안정}     | 상향 슬롯은 `chance ≠ 매우낮음`                                      |
| **공격**  | {상향, 상향, **적정**} | 적정 슬롯은 `chance=높음` **필수** (안전판)                          |

**변경점 1 — 안정 성향: `적정/안정/안정` → `적정/적정/안정`**

정시 3장 중 2장을 안정에 쓰는 것은 안정 성향이라도 과잉입니다. 안정 지원의 목적은 "재수를 피한다" 이고, 그것은 **확실한 안정 1장으로 달성됩니다.** 두 번째 안정 카드는 첫 번째보다 반드시 낮은 대학이 되므로, 합격하더라도 진학하지 않을 카드에 지원 기회 하나를 버리는 셈입니다.

대신 안정 슬롯의 기준을 `+2.0σ`(일반 안정)에서 **`+2.5σ`** 로 올렸습니다. 안정 성향 학생에게는 "안정 중에서도 가장 확실한 것" 을 주는 것이 맞고, 그러면 1장으로 충분합니다.

**변경점 2 — 공격 성향: 적정 슬롯에 `chance=높음` 강제**

`상향/상향/적정` 자체는 타당합니다. 다만 적정 슬롯이 적정 하단(`chance=보통`, 합격률 40~65%)으로 채워지면 **세 장 모두 합격률 65% 미만**이 되어 전원 불합격 확률이 산술적으로 10%를 넘습니다. 공격 성향이 감당하려는 리스크는 "목표를 낮추지 않는 것" 이지 "재수 확률 10%" 가 아닙니다. 적정 슬롯을 `chance=높음`(65~85%)으로 제한하면 전원 불합격 확률이 통제됩니다.

**균형 성향은 잠정안 그대로 유지합니다.** `상향/적정/안정` 은 정시 지원의 교과서적 배분이며 수정할 이유가 없습니다.

### 4.3 군 배정 규칙

```
1. 학생의 희망 조건(preference.target / targetKind / region) 으로 후보를 필터
2. 각 tier 버킷에서 "희망 적합도" 순으로 정렬
   희망 적합도 = category 일치(targetKind=department 면 학과명 일치 가중) × region 일치 × advantageScore
3. 가장 높은 tier(상향 > 적정 > 안정) 슬롯부터 배정
   → 희망 적합도 최상위 모집단위를 고르고, 그 모집단위의 group 을 해당 슬롯의 군으로 확정
4. 남은 두 군에 나머지 tier 를 배정. 각 군 안에서 다시 희망 적합도 순 선택
5. 한 조합 안에서 같은 대학이 두 번 들어가지 않게 함 (분산 지원 원칙)
```

가장 올라가고 싶은 카드(상향)에 희망 학과를 우선 배치하는 것이 지원 심리와 실무 모두에 맞습니다.

### 4.4 폴백 규칙 (해당 tier 가 그 군에 없을 때)

`GroupCombination` 의 `가` / `나` / `다` 가 `null` 을 허용하는 이유입니다.

```
1. 해당 군에 요구 tier 모집단위가 없으면 → 인접 tier 로 1단계 완화
   상향 → 적정 / 적정 → 안정 (안정 방향으로만 완화. 지원불가 방향 완화 금지)
2. 완화해도 없으면 → 그 군 슬롯을 null
3. null 이 발생하면 label 에 명시하고, AI 전략 문장에 사유를 반드시 포함
   예: "다군은 희망 계열에 지원 가능한 모집단위가 없어 비웠습니다"
```

🔴 **상향 방향으로의 완화는 금지합니다.** 빈 슬롯을 채우려고 `적정` 자리에 `상향` 을 넣으면 사용자가 요청한 성향보다 위험한 조합이 만들어집니다. **비워 두는 것이 정직합니다.**

### 4.5 조합 개수

성향별로 **3~5개** 를 제시합니다. 정시 리포트 템플릿(`입시_분석_기능_정보/report_template.png`)의
"실제 원서접수 가능한 최적 조합 3~5개" 가 제품 요구사항입니다.

> 이전 판은 "4개 이상은 사용자가 비교하지 못한다" 며 2~3개로 정했으나, 템플릿 요구와 어긋나 변경했습니다.
> 비교 부담은 조합마다 차별화 축을 `label` 로 붙여 덜어냅니다 — 같은 기준으로 뽑은 조합을 여러 개 늘어놓지 않습니다.

- 축마다 조합 하나를 만들고, 같은 결과(세 슬롯이 모두 같은 모집단위)는 버립니다.
- 축이 겹쳐 3개가 안 되면 앞선 조합에 쓴 대학을 빼고 **희망 우선형 대안**을 만듭니다.
- 후보가 모자라면 3개 미만이어도 그대로 둡니다. 억지로 채우려고 성향 매트릭스(§4.2)나 폴백 규칙(§4.4)을 어기지 않습니다.

| label 예시      | 차별화                                                  |
| --------------- | ------------------------------------------------------- |

## 5. 반영방식 유리도 (`advantageScore`) 산출식

### 5.1 설계 원칙

**유리도에 합격 가능성을 섞지 않습니다.** `advantageScore` 는 "이 대학의 반영방식이 내 성적 구조에 유리한가" 만 측정합니다. tier·chance 를 섞으면 PART 2(유리한 대학)가 PART 3(지원 가능 대학)의 중복이 되어 리포트 한 파트가 통째로 무가치해집니다.

단, PART 2 노출 시 **`tier === "지원불가"` 와 `eligible === false` 인 항목은 목록에서 제외**합니다. 점수에 섞지 않고 필터만 합니다.

🔴 **유리도 점수는 학생에게 보이지 않습니다.** `advantageScore` 는 PART 2 정렬 순서로만 드러나고, 화면·AI 프롬프트 어디에도 숫자로 싣지 않습니다. 학생에게는 반영비율·활용지표가 내 강점과 어떻게 맞물리는지로 설명합니다.

PART 2 는 **대학당 한 곳**만 싣고 희망 범위(적합도 ≥ 계열그룹)를 우선합니다. 같은 대학은 학과가 달라도 반영식이 같아 유리도가 같으므로, 묶지 않으면 상위 5개가 한 대학의 모집단위(식품영양학과 포함)로 채워집니다.

### 5.2 기본 점수 — 편차·비율 내적 정규화

**① 학생 영역별 백분위 벡터**

> **2026-11-05 변경 (사용자 결정): 영어는 백분위 벡터에서 뺀다.** 영어는 원문에 등급만 있고,
> 등급을 백분위로 바꾸는 표(98·92.5·83 …)는 원문 값이 아닌 추정이다. 기본 점수·성적 진단(PART 1
> 순위·편차·강점·약점)·가중 백분위는 국어·수학·탐구 세 영역으로 계산하고, 비율 편차는
> `반영비율 / 국·수·탐 비율 합 − 1/3` 로 본다. 영어의 유리·불리는 대학별 등급 감점·점수표(원문)로
> §5.3 영어 영향력 보정에서만 다룬다. `GRADE_TO_PERCENTILE` 은 엔진에서 지웠고, 아래는 기록으로 남긴다.

<details><summary>폐기된 기존 정의</summary>

```
p_국 = korean.percentile
p_수 = math.percentile
p_탐 = 대학이 1과목 반영이면 상위 1과목 백분위, 2과목이면 두 과목 평균
p_영 = 영어 등급 → 환산 백분위
```

영어 환산 백분위는 **이미 구현된 `GRADE_TO_PERCENTILE`(`libs/jeongsi/engine/convert-score.ts`)을 단일 출처로 사용합니다.** 9등급제 등급별 누적비율(4·11·23·40·60·77·89·96·100%)의 구간 중앙값에서 도출된 값으로, 근거가 문서화되어 있습니다.

| 등급   | 1   | 2    | 3   | 4    | 5   | 6    | 7   | 8   | 9   |
| ------ | --- | ---- | --- | ---- | --- | ---- | --- | --- | --- |
| 백분위 | 98  | 92.5 | 83  | 68.5 | 50  | 31.5 | 17  | 7   | 2   |

> 영어는 절대평가라 백분위가 공개되지 않습니다. 위 표는 **추정값**이며 유리도의 상대 비교 목적에만 씁니다. 환산점수 계산에는 쓰지 않습니다(대학 환산식이 등급별 절대 점수를 직접 주므로).
>
> ⚠️ 실제 영어 절대평가의 등급별 인원 비율은 9등급제 상대평가 비율과 매년 다르게 나옵니다(영어 1등급은 해에 따라 4~13%). 수능 성적 발표 후 **실제 등급 비율로 이 표를 갱신**하면 유리도 정확도가 올라갑니다. 갱신 시에도 `GRADE_TO_PERCENTILE` 한 곳만 고치면 됩니다.

</details>

**② 편차 벡터**

```
mean  = (p_국 + p_수 + p_영 + p_탐) / 4
dev_k = p_k − mean                        // Σdev_k = 0
```

**③ 대학 비율 편차 벡터**

```
r_k    = ratios[k] / 100
rdev_k = r_k − 0.25                       // 균등 배분 기준
```

**④ 내적과 정규화**

```
raw   = Σ_k ( dev_k × rdev_k )
scale = max( |max(dev)|, |min(dev)|, 0.5 )
base  = 50 + 50 × (raw / scale)           // 0 ~ 100
```

정규화 근거: 비율 100%를 학생의 **최강 영역**에 전부 주는 가상의 대학에서 `raw` 가 최대가 되고, 그 값은 정확히 `max(dev)` 입니다 (`Σdev = 0` 이므로 `dev_best × 0.75 − (−dev_best) × 0.25 = dev_best`). 최약 영역에 전부 주면 `min(dev)`. 따라서 `raw / scale ∈ [−1, +1]` 이고, **균등 반영(모두 25%) 대학은 정확히 50점**이 됩니다.

`scale` 하한 0.5: 전 영역이 균일한 학생은 반영방식 유불리가 실제로 없으므로 모든 대학이 50점 근처에 모입니다. 올바른 결과이며, 0 나눗셈도 막습니다.

> **2026-11-04 결정 — 원문 데이터에 없는 값은 만들지 않는다.** 아래 §6.1 대리 컷 추정과

> 결측으로 본다(50%컷·평균으로 대신하지 않는다). 전국 최고점·환산 만점이 원문에 없어

### 6.1 입결이 아예 없는 모집단위 (신설)

샘플 데이터의 한양대 반도체공학과, 가천대 인공지능학과, 충남대 데이터사이언스학과가 이 경우입니다.

**대리 컷 추정 우선순위**

```
1. 같은 대학 + 같은 category, 다른 군 → 그 컷을 그대로 사용
2. 같은 대학 + 같은 계열(인문/자연) 모집단위들의 컷 중앙값 + 0.3 백분위점
3. 같은 category 의 타 대학 컷을, 두 대학의 계열 평균 컷 차이로 보정해 사용
4. 1~3 모두 불가 → tier = "적정", chance = "보통", 추정 불가 명시
```

`+0.3 백분위점` 근거: 신설 모집단위는 입결 정보가 없어 지원을 꺼리는 효과(컷 하락)와, 최근 신설이 AI·반도체·데이터 등 선호 분야에 집중되는 효과(컷 상승)가 함께 작용합니다. 두 효과가 상당 부분 상쇄되므로 소폭 상향만 적용합니다.

**필드 처리 (중요)**

| 필드                              | 값                                            |
| --------------------------------- | --------------------------------------------- |
| `PlanEvaluation.referenceCut`     | **`null` 유지**                               |
| `PlanEvaluation.gapRatio`         | **`null` 유지**                               |
| `RecommendationItem.referenceCut` | **`null`**                                    |
| `UniversityDetailItem.cutHistory` | 3개년 모두 `{ year, cut: null }`              |

### 6.1-b 후보 풀 확대 — 단일 `category` 필터로는 추천을 못 채웁니다

🔴 (교체 전 샘플 기준) 샘플 데이터 156개 모집단위의 카테고리는 **48종**이고, 그중 **45종이 9개 미만**, **26종은 단 1개**입니다. `recommendations` 는 구분별 3개씩 총 9개가 필요하므로, `category` 완전일치로만 후보를 뽑으면 철학·역사학·수학·정치학 지망생은 후보가 1개뿐이어서 세 밴드 중 둘이 반드시 빕니다.

**단계적 확대 규칙 — 후보 개수가 아니라 "밴드가 찼는가"로 판단합니다**

```
Stage 1: category 완전일치
   → 분류 후 상향·적정·안정 세 밴드가 모두 ≥ 3 이면 종료
Stage 2: + 같은 계열그룹 (+ 계열무관: 자유전공·공학계열, 단 이름에 다른 대계열이 드러난 모집단위 제외)
   → 적정 밴드가 ≥ 1 이면 종료        ← 적정만 본다
~~Stage 3: + 같은 대계열(인문/자연) 전체~~ — **2026-11-08 폐기.** 적정을 메우려고 넓혔더니 전자공학 희망 학생에게 식품영양학과·수학과가 적정 추천으로 나갔다. 후보는 Stage 2(계열그룹)까지만 모으고, 적정이 비면 비었다고 안내한다.
   → 종료 (더 확대 없음)
```

🔴 **Stage 3 은 적정이 한 곳도 없을 때만 엽니다.** 종료 기준을 적정 ≥ 3 으로 두면 입결 없는 모집단위를 뺀 뒤 서울 컴퓨터공학 지망생이 곧바로 Stage 3 에 들어가, 조합에 서울대 식품영양학과·강서대 식품영양학과가 들어왔습니다(실측). 적정이 1~2곳이면 §6.1-d 근접 대체로 채우고, 희망과 무관한 학과로 슬롯을 채우지 않습니다.

🔴 **계열무관이어도 이름에 계열이 드러나면 따릅니다.** `서울대 인문계열`의 category 는 자유전공이지만 이과 컴퓨터공학 지망생의 대안이 아닙니다(`matchesNeutralPlanField`).

확대는 **후보 풀에만** 적용하고 `preference.target` 적합도 정렬(§4.3)로 희망 학과를 계속 상위에 둡니다. 확대 후보는 적합도 가중을 낮춥니다(계열그룹 0.5 / 대계열 0.25).

🔴 **후보 "개수" 임계값을 쓰지 마세요.** 개수는 밴드가 채워지는지를 알려주지 않습니다. 같은 19개라도 컷이 18 백분위점에 퍼져 있으면 밴드(폭 1.68점)당 1.8개뿐이고, 3 백분위점에 몰려 있으면 한 밴드에 다 들어갑니다. 측정한 밀도:

| 후보        | 모집단위 수 | 컷 분포          | 밴드당 기대 |
| ----------- | ----------- | ---------------- | ----------- |
| 경영학 단일 | 19          | 80.6~98.3 (18점) | **1.8개**   |
| 경상그룹    | 44          | 동일             | 4.1개       |

또한 개수 임계값은 **데이터 규모가 바뀌면 재조정해야 합니다.** 샘플은 20개 대학이지만 실제 정시 모집 4년제는 약 190개 대학이라, 실데이터에서 경영학 모집단위는 180개 수준이 되고 밴드당 기대가 16.8개로 올라갑니다. 그 시점에는 확대가 불필요해지는데, 개수 임계값은 그 전환을 스스로 감지하지 못합니다. **밴드 충족 조건은 양쪽 규모에서 모두 자동으로 올바르게 동작합니다.**

**Stage 2 → 3 에서 적정만 보는 이유**: 적정은 세 성향 조합이 **모두** 요구하는 유일한 필수 밴드입니다(§4.2 — 안정 {적정,적정,안정} / 균형 {상향,적정,안정} / 공격 {상향,상향,적정}). 상향·안정은 비어도 §6.1-d 대로 빈 배열을 허용합니다. 최상위권 학생의 상향이 구조적으로 0 이라는 이유로 대계열까지 끌어오면 희망과 무관한 학과가 추천에 섞입니다.

> 개수 임계값으로 이미 구현했다면 **24** 가 차선입니다(3밴드 × 3개 + 대학 중복 제거 여유). 샘플 데이터에서는 거의 모든 카테고리가 24 미만이라 사실상 "항상 1단계 확대"로 동작하며, 중위권 적정이 3개로 찹니다. 다만 실데이터 전환 시 재검토가 필요합니다.

> **일반 원칙**: **면허·자격 연계 트랙은 대계열 확대를 금지합니다.** 현재 해당 그룹은 의약 · 보건 · 교육입니다. 이 트랙들은 학과 전환이 자유롭지 않아, 계열그룹을 넘는 추천이 사용자에게 쓸모가 없습니다. 그 결과 상향·안정 밴드가 덜 차더라도 §6.1-d 대로 **빈 배열을 허용**합니다 — 관련 있고 불완전한 추천이 완전하고 무관한 추천보다 낫습니다.

두 분포가 약 7 백분위점 간격으로 거의 겹치지 않습니다. 한 그룹으로 묶으면 **백분위 98 의대 지망생의 "적정" 추천이 간호학과 3개로 채워집니다** — 실제로 그렇게 재현됐습니다. 실무적으로도 의대 지망생의 하향 선택지는 치·한·수의·약이고 간호는 별도 트랙입니다. 보건 그룹은 화학·생명 그룹과 양방향 확대를 허용합니다.

> 이전 판에서 간호학을 의약·보건 한 그룹으로 묶은 것은 **작성자 오류**입니다. "컷이 극단적이라 분리한다"는 근거가 간호학에는 적용되지 않습니다.

### 6.1-c `category` → 인문/자연 계열 판정

데이터에 계열 필드가 없으므로(타입에 없음) `category` 로 유도합니다.

- **자연**: 컴퓨터·IT / 전기전자 / 기계·건설 / 화학·생명 / 수리·자연 / 의약 / 보건 그룹 전체
- **인문**: 경상 / 사회 / 인문 그룹 전체
- **판정 불가**: 계열무관(`자유전공` · `공학계열` 등) · 교육 · 예체능·디자인 그룹 → 계열 판정이 필요한 로직에서는 **전체 모집단위**를 모집단으로 사용
  - 교육은 국어교육(인문)과 과학교육(자연)이 한 그룹에 있고, 예체능·디자인은 대학마다 인문·자연 모집이 갈립니다. 둘 다 면허 트랙이거나 Stage 3 를 써도 무관 추천이 되므로 대계열을 두지 않습니다

⚠️ 경상 그룹을 인문으로 둔 것은 **대학 모집단위 구분 기준**입니다. 실제로는 경영·경제를 자연계 학생이 교차지원하는 비율이 높지만, 이 판정은 "대리 컷 추정 시 어느 모집단을 쓸지" 에만 쓰이므로 모집단위 구분을 따르는 것이 맞습니다.

### 6.1-d 밴드가 비었을 때

후보 풀을 최대로 확대해도 특정 tier 가 0개면:

- **적정이 3개 미만인 경우** 🔴: 세 성향 조합 모두 적정 슬롯을 포함하고 안정 성향은 적정을 **2개** 요구하므로(§4.2), 0개일 때만이 아니라 **3개 미만이면** 보충합니다. 적정 밴드에 가장 가까운 항목(상향 상단 또는 안정 하단)을 `percentileGap` 거리순으로 끌어오고, AI 해설에 "희망 조건에 정확히 적정인 모집단위가 없어 가장 가까운 곳을 제시했습니다" 를 명시합니다.

  🔴 **거리 상한 `1.5σ` 를 두세요.** 적정 밴드 경계(−0.4σ / +2.0σ)로부터 1.5σ 넘게 떨어진 항목은 끌어오지 않습니다. 상한이 없으면 터무니없는 추천이 들어옵니다 — 실측 사례로 백분위 98 학생의 적정 버킷에 컷 85~90 인 간호학과(+7.9σ)가 들어왔습니다. 상한을 넘으면 **채우지 말고 비워 둡니다.** 끌어온 항목의 `tier` 는 절대 덮어쓰지 않습니다(§9 #9).

  🔴 **다른 밴드에 이미 뽑힌 모집단위는 끌어오지 마세요.** 실측 사례로 `가천대학교-간호학과-다` 가 **적정 버킷(tier=안정, 근접 대체)과 안정 버킷에 동시 등장**했습니다. 학생은 PART 3 에서 같은 학과를 두 섹션에서 보게 되고, 둘 다 `안정` 라벨이라 "왜 같은 곳이 두 번 나오지?" 로 읽힙니다. 근접 대체 후보에서 이미 선정된 `plan.id` 를 제외하세요. 대학 단위가 아니라 **모집단위(`plan.id`) 단위**로 제외하면 됩니다 — 같은 대학의 다른 학과·군이 서로 다른 밴드에 오는 것은 정상입니다.

  🔴 **중복 금지가 "적정 채우기" 보다 우선입니다.** 끌어올 후보가 전부 다른 밴드에 이미 노출돼 있으면 **적정을 비워 둡니다.** 이미 화면에 보이는 모집단위를 적정 칸에 복제하면 정보량이 0 이고 혼란만 늘어납니다 — 학생은 가장 가까운 선택지를 상향·안정 섹션에서 이미 보고 있습니다.

  즉 적정이 비는 경로가 두 가지입니다:
  - **거리 상한 초과** → 가까운 후보가 없음
  - **전부 중복** → 가까운 후보가 이미 다른 섹션에 노출됨

  두 경우의 안내 문구가 달라야 합니다(§8-b.4). 그리고 이때 `moderateBandSubstituted` 는 **`false`** 입니다 — 실제로 대체가 일어나지 않았으므로.

- **상향·안정이 빈 경우** 🟡: 빈 배열 그대로 내보내고 사유를 해설에 씁니다. 상향이 비는 것은 "현 성적으로 더 올라갈 곳이 데이터에 없다"(최상위권) 또는 "희망 조건이 좁다" 는 **정보**이지 오류가 아닙니다. 억지로 채우면 지원불가를 상향으로 승격시키게 됩니다.

### 6.1-e 선택과목 제한으로 희망 계열이 전멸하는 경우 🔴

정시 분석에서 **가장 중요한 단일 정보**인데 현재 전달 경로가 없는 케이스입니다.

샘플 데이터의 의약 모집단위 9개는 **전부** `restrictions` 를 가집니다(과탐필수 4 / 과탐1과목이상 5, 그중 3개는 미적·기하까지). 따라서 **확률과통계 + 사회탐구 응시자가 지원 가능한 의약 모집단위는 0개**입니다.

문제는 엔진이 `eligible === false` 를 `advantageousPlans` 와 `recommendations` 에서 **모두 필터링**하므로, 학생은 "왜 의대가 한 곳도 안 나오는지" 를 끝까지 알 수 없다는 점입니다. 희망 학과를 의학으로 입력한 사용자에게 이 침묵은 치명적입니다.

**처리 규칙**

```
판정 범위 = Stage 1(category 완전일치) + Stage 2(같은 계열그룹)
            ※ Stage 3(대계열) 확대분은 범위에서 제외

그 범위의 후보가 모두 eligible=false 면:
  1. recommendations 세 밴드를 모두 빈 배열로 둔다 (다른 계열로 대체 금지)
  2. combinations 도 빈 배열
  3. advantageousPlans 도 빈 배열
  4. diagnosis(성적 분석)는 그대로 제공 — 수능 성적 진단 자체는 유효하다
  5. AI 해설이 "응시 과목 제한으로 지원 자체가 불가능하다"를 최우선 서술
```

**판정 범위에 Stage 2 를 포함하는 이유**: Stage 1 만 보면, 희망 category 는 전멸이지만 같은 계열그룹에 지원 가능한 곳이 **있는데도** 추천을 통째로 비우게 됩니다. 예를 들어 의학 지망생의 의예과가 전부 불가하더라도 수의예·한의예가 지원 가능하다면, 그건 전멸이 아니라 **하향 선택지가 있는 상황**입니다(의대 지망생의 현실적 선택지는 치·한·수의·약). 그 경우 수의예를 추천하면서 의대 불가 사실을 함께 설명하는 것이 올바른 출력입니다.

**Stage 3 를 범위에서 제외하는 이유**: 거기까지 끌어오는 것이 위에서 금지한 "다른 계열로 대체" 입니다. 컴퓨터공학 지망생의 컴퓨터·IT 그룹이 전부 제한에 걸리면, 기계공학이 지원 가능해도 전멸 판정을 유지합니다.

⚠️ **"과탐필수" 제한은 과탐 응시자를 통과시킵니다.** 제한의 존재 자체가 전멸을 뜻하지 않습니다. 샘플 데이터 실측: 과탐·미적 응시자에게 의학 5개·수의학 2개·한의학 1개·약학 1개가 **전부 eligible** 이고, 사탐·확통 응시자에게만 9개 전부 ineligible 입니다. 전멸 판정은 반드시 `checkEligibility` 결과로 하고, `restrictions` 유무로 추정하지 마세요.

🔴 **다른 계열로 대체하지 마세요.** 의대 지망생에게 간호학과나 생명과학과를 추천하는 것은 질문에 답하지 않는 것입니다. 지원 불가 사실을 알리는 것이 유일하게 유용한 출력입니다.

**AI 레이어의 감지 방법 (타입 변경 없이 가능)**: `JeongsiAnalysis.input` 에 학생의 선택과목이 들어 있으므로, `recommendations` 가 전부 비어 있을 때 `input.score.math.elective` 와 `input.score.inquiry1/2.subject` 로 제한 불충족을 직접 판정할 수 있습니다. 프롬프트 규칙은 §8 에 있습니다.

> 📌 근본 해결은 `JeongsiAnalysis` 에 `ineligiblePlans: PlanEvaluation[]` 를 추가하는 것입니다. §9 #10 으로 보고합니다.

### 6.2 지표가 다른 입결 (percentile vs convertedScore)

> **2026-11-08 결정 (사용자 승인):**
>
> - 백분위 입결은 원문 `inquiryHandling` 이 **"2과목 평균"인 행만** 쓴다(엔진 단순평균과 같은 기준).
>   "미공개"를 2과목 평균으로 간주하던 처리는 원문에 없는 값을 가정한 것이라 폐기했다. 입결이 모두 사라진
>   161개 모집단위는 서비스 데이터에서 빠졌다(1294 → 1143).
> - 탐구 변환표준점수는 학생이 실제 응시한 과목(사탐·과탐)의 열로 환산한다. 모집단위 계열로 열을 고르지 않는다.
>   원문에 없는 열(“해당없음”)은 만들지 않고, 그 과목으로는 환산할 수 없는 것으로 본다.

**원칙: 학생 점수를 입결 지표에 맞춥니다.** 입결을 환산점수로 역변환하면 정보 손실과 오차가 커집니다.

| 입결 `metric`    | 비교 대상                            | `gapRatio` 산출                   | `percentileGap`          |
| ---------------- | ------------------------------------ | --------------------------------- | ------------------------ |
| `convertedScore` | `PlanEvaluation.convertedScore`      | `(학생 − 컷) / totalScore × 100`  | `gapRatio / sensitivity` |
| `percentile`     | 학생의 국·수·탐 **단순 평균 백분위** | `학생 평균백분위 − 컷` (백분위점) | `gapRatio` **그대로**    |

🔴 **`percentile` 입결에 `weightedPercentile`(대학 반영비율 가중) 을 쓰지 마세요.** 공개된 백분위 입결(대학어디가 공시 등)은 거의 전부 **국·수·탐 단순 평균**입니다. 가중 평균과 비교하면 강점이 있는 학생은 체계적으로 과대평가되고 약점이 있는 학생은 과소평가됩니다. `weightedPercentile` 은 `advantageScore` 와 표시용으로만 씁니다.

> 📌 **보고 사항 (데이터 스펙 보완)**: 현재 `ResultCut` 에는 백분위 입결의 **산출 기준**(국수탐 단순평균 / 국수영탐 평균 / 대학 자체 가중)이 없습니다. 실데이터에서는 대학마다 다를 수 있으므로 `ResultCut` 에 `basis?: "국수탐단순평균" | "국수영탐단순평균" | "대학가중"` 필드를 추가하는 것을 권합니다. 추가 전까지는 **전부 국수탐 단순평균으로 간주**합니다.

**혼재 시 UI 규칙**: 같은 추천 목록에 두 지표가 섞여도 `tier`/`chance` 는 `percentileGap` 으로 통일되어 비교 가능합니다. 다만 숫자 표시는 **단위 라벨을 반드시 붙여야** 합니다.

- `percentile` 기준: `"백분위 94.5 (내 백분위 95.2)"`
- `convertedScore` 기준: `"환산 912.4 / 컷 908.1 (1000점)"`

라벨 없이 나란히 놓으면 사용자가 912 와 94.5 를 같은 축으로 읽습니다.

#### 리포트 표시 — 컷은 단위를 붙이고, 같은 지표의 학생 값과 나란히 둔다 🔴

실데이터 입결은 대부분 국·수·탐 평균 **백분위**이고 일부만 대학 환산점수입니다. PART 3·5 가 "내 환산점수 659점"
옆에 "기준컷 96.1" 을 두면 단위가 다른 숫자를 비교하게 됩니다. 리포트 항목은 `cutComparison`
(`metric` · 같은 지표의 학생 값 · 3개년 기준컷 · 전년도 실제 컷)을 싣고, 화면과 AI 프롬프트 모두
컷 값에 단위("백분위 96.1" / "566.9점")를 붙입니다. 환산점수는 템플릿 항목이라 함께 보여주되 컷과 직접 비교하지 않습니다.

### 6.2-b 입결 컷의 가산점 포함 기준 🔴

**`metric: "convertedScore"` 입결에만 해당합니다.** `percentile` 입결은 환산 전 지표여서 가산점 개념이 없습니다(샘플 데이터도 백분위 컷은 환산식을 통과시키지 않고 난이도 백분위를 그대로 씁니다).

**샘플 데이터의 기준**: 입결 컷은 난이도 백분위의 가상 학생을 환산식에 통과시켜 역산했고, 그 가상 학생의 선택과목은 계열별로 고정했습니다.

| 계열 | 수학 선택  | 탐구       | 가산 수혜     |
| ---- | ---------- | ---------- | ------------- |
| 자연 | 미적분     | 과탐 2과목 | **전부 수혜** |
| 인문 | 확률과통계 | 사탐 2과목 | 해당 없음     |

`bonus` 는 자연 계열 환산식에만 있고 자연 가상학생은 미적분·과탐을 응시하므로, **가산 보유 모집단위의 환산점수 컷에는 가산점이 포함**되어 있습니다.

단, **"가산 포함 = 총점 초과" 가 아닙니다.** 가산 보유 32개 중 환산점수 입결은 6개이고 `totalScore` 초과는 2개뿐입니다:

| 모집단위                | 컷 / 총점                   |
| ----------------------- | --------------------------- |
| 부산대 정보컴퓨터공학부 | 912.84 / 1000 (91.3%)       |
| 부산대 기계공학부       | 903.51 / 1000 (90.4%)       |
| 경북대 컴퓨터학부       | 887.50 / 1000 (88.8%)       |
| 경북대 신소재공학부     | 873.39 / 1000 (87.3%)       |
| **부산대 의예과**       | **1006.68 / 1000 (100.7%)** |
| **경북대 의예과**       | **1007.24 / 1000 (100.7%)** |

초과는 백분위 99 이상의 극상위 컷에서만 발생하며 최대 0.7% 입니다. 또 전체 초과 6건 중 3건(연세대 의예)은 **가산이 없고 한국사 가산(`history.type === "add"`) 때문**입니다. 즉 초과 원인이 두 갈래이므로, UI 는 "가산 보유면 초과" 로 가정하지 말고 **≤ 와 > 를 모두 처리**해야 합니다.

#### 실데이터 전환 시의 함정 🔴

컷이 **가산 제외** 기준인데 학생 점수에 가산이 붙으면, **가산 수혜자만 선택적으로 과대평가**됩니다.

- 미적분·과탐 응시자: 점수가 1.6~5% 부풀려져 상향이 적정으로 보임 → 실제 불합격
- 확률과통계 응시자: 영향 없음

일률 편향이 아니라 **차별적 편향**이라 더 위험합니다. 역방향(컷은 가산 포함, 학생은 미수혜)은 문제가 없습니다 — 그게 실제 불리함입니다.

대부분의 대학은 가산을 환산식의 일부로 보아 **최종 환산총점(가산 포함)** 으로 입결을 공개합니다. 그러나 "수능 환산점수" 와 "총점" 을 분리 공시하는 대학이 있고, 특히 **외주업체가 엑셀로 옮기는 과정에서 어느 쪽인지 소실될 위험**이 큽니다.

**처리 규칙**

```
ResultCut.bonusIncluded (기본값 true)
  true  → 컷이 BonusPolicy 가산점을 반영한 값. 학생 convertedScore 와 직접 비교
  false → 가산 전 환산점수. 학생 쪽도 가산을 뺀 값으로 비교
          비교값 = conversion.convertedScore − conversion.bonusAdjustment
```

🔴 **이 플래그의 적용 범위는 `BonusPolicy` 가산점(수학 선택과목·과탐)뿐입니다.** 영어·한국사는 **항상 컷에 포함된 것으로 간주**하며 뺄셈 대상이 아닙니다.

근거: 영어·한국사는 환산식의 구성 요소로 발표되므로 입결에서 분리되는 일이 사실상 없습니다. 반면 수학 선택·과탐 가산점은 "별도 가산 항목" 으로 발표되는 경우가 있어 입결이 가산 전 점수일 수 있습니다.

⚠️ 다만 한국사 가산(최대 총점의 1%)이 실제로 컷에서 빠진 대학이 발견되면 격차가 약 0.8 백분위점(σ=0.7 기준 **1.1σ**) 어긋나 tier 가 한 단계 바뀔 수 있습니다. 실데이터 검수에서 "수능환산점수" 와 "총점" 을 분리 공시하는 대학을 만나면 **한국사 포함 여부까지 확인**하고, 분리된 사례가 유의미하게 많으면 플래그를 분리하는 것을 재검토하세요.

`ScoreConversion` 이 이미 `bonusAdjustment` 를 분리해 들고 있으므로 보정은 뺄셈 한 번입니다. 필드가 없는 동안에는 **`true`(가산 포함)로 간주**하고, 그 가정을 `specs/012` 수집 요건에 명시합니다.

### 6.3 컷 종류 결측

**우선순위: `cut70` > `cut50` > `average`**

70%컷을 1순위로 쓰는 이유: **최종등록자 상위 70% 지점이 실질 합격선**입니다. 50%컷과 평균은 상위 등록자에 끌어올려져 합격선을 과대평가하며, 그대로 쓰면 적정을 상향으로 잘못 분류해 지원 가능한 대학을 놓치게 만듭니다.

`cut70` 이 없을 때 (샘플에는 없지만 실데이터에서 발생 가능):

| 대체 컷   | 보정               | `chance`     |
| --------- | ------------------ | ------------ |
| `cut50`   | **− 0.5 백분위점** | 한 단계 하향 |
| `average` | **− 0.8 백분위점** | 한 단계 하향 |

보정값 근거: 정시 입결에서 상위 50% 지점과 70% 지점의 전형적 격차는 백분위 0.4~0.6점, 평균과 70% 지점은 0.7~1.0점입니다. 환산점수 지표라면 `보정 × sensitivity × totalScore / 100` 으로 변환해 적용합니다.

### 6.4 3개년 중 일부 연도 결측

`admissionYear` 가 빠진 연도는 **가중치 재정규화**로 처리합니다 (§3.1 ①). 2개년 이하면 추세 보정을 끄고(`trend = 0`), 1개년이면 `σ_obs` 를 쓸 수 없으므로 `σ = σ_min` 을 씁니다.

`additionalPassCount` 결측은 보정에 쓰지 않으므로(§3.3) 영향이 없습니다.

| 내부 용어 금지                    | `계열그룹` · `대계열` · `격차` · `적정 구간` · `밴드` · `모집단위`(가능하면) 는 학생 어휘가 아닙니다                                                                                                                                                                                                           |
| 사유 → 사실 → 행동                | 무엇이 일어났는지, 왜, **그래서 무엇을 하면 되는지** 순서로 씁니다                                                                                                                                                                                                                                             |
| 결핍 서술 금지                    | "부족해서" 는 학생 잘못으로 읽힙니다. 원인이 대학 모집 현황이면 그쪽에 귀속시킵니다                                                                                                                                                                                                                            |
| 중복 금지                         | 같은 정보를 한 문구 안에서 두 번 말하지 않습니다                                                                                                                                                                                                                                                               |
| 괄호 중첩 금지                    | 괄호 안에 완전한 문장이나 또 다른 괄호를 넣지 않습니다                                                                                                                                                                                                                                                         |
| 조사 처리                         | `은(는)` 같은 표기를 노출하지 않습니다. 종성 판정으로 조사를 고릅니다                                                                                                                                                                                                                                          |
| **플래그가 아니라 데이터로 판단** | 🔴 안내 문구의 분기는 `selection` 플래그보다 **`recommendations` 의 실제 내용**을 1차 기준으로 삼습니다. 이번 작업에서 반복된 모순이 전부 이 유형입니다 — 전멸인데 "넓혀 비교했습니다" / 비었는데 "담았습니다" / 없는 목록을 가리키기. 플래그는 의도를, 데이터는 결과를 말하고 **학생이 보는 것은 결과입니다** |

```ts
/** 종성 유무로 주격 보조사를 고른다 */
const withTopicJosa = (word: string): string => {
  const code = word.charCodeAt(word.length - 1);
  const hasFinalConsonant =
    code >= 0xac00 && code <= 0xd7a3 && (code - 0xac00) % 28 !== 0;
  return `${word}${hasFinalConsonant ? "은" : "는"}`;
};
```

### 8-b.2 `blockedByRestrictions` — 지원 불가

🔴 **사유를 문장 단위로 이어붙이지 말고 "요건 차원"으로 집계하세요.** 현재 구현은 `ineligibleReason`(완전한 문장)을 `/` 로 이어 괄호에 넣어, 실측 결과 **202자 / 괄호 3중 중첩 / 응시 과목 2회 중복**이 나옵니다:

> 희망하신 의예과은(는) 수능 선택과목 제한으로 지원할 수 있는 모집단위가 없습니다. (탐구 2과목 모두 과학탐구를 응시해야 지원할 수 있습니다. (응시 과목: 생활과윤리·사회문화) / 탐구에서 과학탐구를 1과목 이상 응시해야 지원할 수 있습니다. (응시 과목: 생활과윤리·사회문화) / 수학 확률과통계 응시자는 지원할 수 없습니다. (지원 가능: 미적분·기하))

제한은 **수학 / 탐구 두 차원**뿐이므로 차원별로 합집합을 만들면 사유가 2개로 정리되고 `MAX_INELIGIBLE_REASONS` 절삭도 불필요해집니다.

```
수학 요구 = 차단된 plan 들의 restrictions.math 합집합    → "미적분 또는 기하"
탐구 요구 = restrictions.inquiry 값 집합
            {과탐필수}            → "과학탐구 2과목"
            {과탐1과목이상}        → "과학탐구 1과목 이상"
            둘 다 존재            → "과학탐구 1~2과목"
학생 응시 과목 = 문구 전체에서 1회만 서술
```

**확정 문안**

> 희망하신 **{target}**{조사} 정시에서 수능 응시 과목 조건이 있어, 현재 응시 과목(수학 {수학선택}, 탐구 {탐구1}·{탐구2})으로는 지원할 수 있는 곳이 없습니다. 이 계열은 **{수학 요구}**와 **{탐구 요구}**를 요구합니다. **희망 계열을 바꿔 다시 분석해 보세요.**

🔴 **마지막 행동 안내는 반드시 넣으세요.** 이 리포트에서 가장 결과가 무거운 문구인데 "불가능하다" 로 끝나면 학생은 멈춥니다.

**확정(2026-10-12)**: `/jeongsi` 입력 폼에서 즉시 재분석이 가능하고 매번 새 리포트가 생성되므로, 재분석 안내 문구를 씁니다. 위 확정 문안이 그것입니다.
원칙은 **제품에 실제로 없는 기능을 암시하지 않는 것**이므로, 재분석 UX 가 제거되면 "다른 계열을 기준으로 전략을 세우셔야 합니다" 같은 전략 차원 안내로 되돌립니다.

🟡 **"다음 수능에서 과탐·미적분을 응시하면 지원 가능하다"는 사실은 기본 노출하지 않습니다.** 정확한 정보지만 자동 리포트가 재수를 권하는 것으로 읽힙니다. 제품 오너가 명시적으로 원할 때만 넣습니다.

🔴 **`blockedByRestrictions` 가 true 면 이 문구만 내보내세요.** §6.1-e 판정 범위가 Stage 1+2 이므로 전멸 시에도 `poolStage` 가 2 일 수 있고, 그러면 "같은 계열까지 넓혀 비교했습니다" 와 "지원할 수 있는 곳이 없습니다" 가 **동시에 노출되어 모순**됩니다. 추천이 빈 배열인 상태에서 확대·대체 안내는 의미가 없습니다.

### 8-b.3 `poolStage` — 후보 확대

현재 문안의 "정확히 일치하는 모집단위가 **부족해**" 는 학생 잘못으로 읽히고, `계열그룹`·`대계열` 은 내부 용어입니다. **확대는 선택지를 넓혀 준 서비스 행위**이므로 그렇게 읽히게 씁니다. 원인은 **대학 모집 현황**에 귀속시킵니다.

**확정 문안** — 행동을 먼저, 이유를 뒤에

> **Stage 2**: 희망하신 **{target}** 외에 **{계열명}**({예시 학과 2~3개} 등)까지 함께 비교했습니다. 희망 지역({region})의 {target}만으로는 현재 성적에 맞는 지원처를 고루 찾기 어려워 비교 범위를 넓혔습니다.
>
> **Stage 3**: 희망하신 **{target}** 외에 **{인문/자연}계열** 전체까지 함께 비교했습니다. 희망 지역({region})의 {target} 및 인접 계열만으로는 현재 성적에 맞는 지원처를 고루 찾기 어려워 비교 범위를 넓혔습니다.

"모집하는 대학이 많지 않아"는 쓰지 않습니다. 확대의 실제 원인은 희망 지역과 성적대의 조합이고, 컴퓨터공학처럼 모집 대학이 많은 학과에서는 사실과 다릅니다.

**구체적인 계열명을 넣으세요** — "계열그룹" 보다 "경상계열(경제·회계·무역 등)" 이 훨씬 유용하고, 학생이 추천 목록에 섞인 학과를 납득할 수 있습니다(철학 지망생의 목록에 사학과가 보이는 이유를 이 문구가 설명합니다). 예시 학과는 §6.1-b 그룹 표에서 2~3개만 뽑습니다.

### 8-b.4 `moderateBandSubstituted` — 적정 대체

"적정 구간" · "격차" 를 쓰지 않고, **실제 분류는 목록에서 확인하라**고 안내합니다. 끌어온 항목은 `tier` 를 유지하므로(§9 #9) 목록의 구분 표시가 진실입니다.

**분기는 적정 버킷의 항목 수를 1차 기준으로, 플래그를 2차로 봅니다.**

```
if (recommendations.적정.length === 0)      → 비어 있다는 문구
else if (selection.moderateBandSubstituted) → "담았습니다" 문구
else                                        → 문구 없음
```

플래그를 1차 조건으로 두면 안 됩니다. 플래그는 **의도**를, 적정 버킷은 **결과**를 말하고 학생이 보는 것은 결과입니다(§8-b.1 마지막 원칙). 플래그 의미가 나중에 "시도했다" 로 바뀌어도 이 분기는 올바른 문구를 냅니다.

**확정 문안 — 대체가 일어난 경우**

> 현재 성적에 정확히 '적정' 으로 분류되는 곳이 많지 않아, 가장 가까운 곳을 함께 담았습니다. 각 대학의 실제 분류는 목록의 구분 표시를 확인해 주세요.

**확정 문안 — 적정이 비어 있는 경우**

뒷문장은 **실제로 차 있는 밴드만 가리키도록 조립**합니다. 비어 있는 섹션을 보라고 하면 안 됩니다.

| 상향 | 안정 | 문구                                                                                                            |
| ---- | ---- | --------------------------------------------------------------------------------------------------------------- |
| 있음 | 있음 | 현재 성적에 '적정' 으로 분류되는 곳이 없습니다. 가장 가까운 선택지는 아래 **상향·안정** 목록에서 확인해 주세요. |
| 있음 | 없음 | …가장 가까운 선택지는 아래 **상향** 목록에서 확인해 주세요.                                                     |
| 없음 | 있음 | …가장 가까운 선택지는 아래 **안정** 목록에서 확인해 주세요.                                                     |
| 없음 | 없음 | 현재 성적에 '적정' 으로 분류되는 곳이 없습니다. **(뒷문장 생략)**                                               |

마지막 행은 현재 도달 불가입니다(세 밴드가 모두 비면 §6.1-e 전멸 경로로 빠져 이 안내가 나가지 않음). 그래도 조립 함수 안에서 처리해 두세요 — 조기 반환 조건이 바뀌면 `아래  목록에서` 같은 깨진 문장이 노출됩니다.

### 8-b.5 `target` 노출 주의

`input.preference.target` 은 사용자 자유 입력입니다("의대" · "의예과" · "의학과" 등). 문구에 그대로 노출하는 편이 친근하지만, 입력이 비정상일 때 문장이 깨질 수 있습니다. 노출 전 길이·공백을 검증하고, 비정상이면 정규화된 `category` 명으로 대체합니다.
